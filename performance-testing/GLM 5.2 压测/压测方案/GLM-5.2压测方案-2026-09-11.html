AI 运营平台 GLM 5.2 API性能压测方案

测试环境：http://198.51.100.10/v1

唯一模型：glm-5.2-test

工具：Apache JMeter 5.6.3，非GUI模式

固定问题：给出一套成都旅游一日游方案，50字左右

请求口径

json
{
  "model": "glm-5.2-test",
  "messages": [
    {
      "role": "user",
      "content": "给出一套成都旅游一日游方案，50字左右"
    }
  ],
  "temperature": 0.2,
  "max_tokens": 32768,
  "stream": false
}

GLM 5.2会先输出推理Token。实测max_tokens=100和512时推理耗尽上限、正文为空；1024三次预检仍有一次正文为空；2048在25线程校准运行358个样本中出现7次空正文；8192在25线程校准运行482个样本中仍出现3次超长推理导致的空正文。因此正式压力测试采用32768。该参数是输出上限，模型以finish_reason=stop完成时会提前结束，并非每次强制生成32768 Token。

为避免客户端在极端长推理尚未完成时提前中断，GLM专属JMeter读取超时为300秒；连接超时仍为10秒。超时配置变更只适用于GLM，不修改KIMI历史测试口径。

采用两级闸门：当前档总体失败率持续达到30%时立即优雅停止；一档结束后总体失败率或429、5xx、超时/重置、空正文、非法JSON、SSE不完整中的任一类达到10%，则该档判为失稳并禁止继续升级。401/403鉴权错误、压测机持续过载时立即停止。该口径用于模型改名为glm-5.2-test后的续测，不回写历史测试结论。

统计口径

流式和非流式分开统计。每档记录Samples、成功率、RPS、Avg、P50、P90、P95、P99、Max、Connect、Latency、401、403、429、5xx、超时、重置、空正文、非法JSON和SSE未完成。JMeter普通Latency不能命名为TTFT；真正首Token时间需要平台或供应商分段日志。

所有结果仅代表“Token平台 + GLM 5.2供应商”的端到端链路。没有平台和供应商服务端监控时，不单凭JMeter结果确定瓶颈归属。
