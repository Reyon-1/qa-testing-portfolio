## 一、用例结构约定

每条用例统一采用三段式结构，便于评审与执行：

```
tc:验证输入错误密码点击登录提示用户名或密码错误，停留在登录页
 ├─ pc:登录页已打开，用户名和密码输入框可见        ← 前置条件 Precondition
 ├─ 步骤:输入 admin / 错误密码 → 输入正确验证码 → 点击登录
 └─ 预期:提示"用户名或密码错误"，页面停留在登录页   ← 预期结果
```

- `tc:` 用例节点（926 条）
- `pc:` 前置条件（926 条）
- `步骤:` 操作步骤（926 条）
- `预期:` 预期结果（926 条）

节点总数 4114 = 926 条用例 + 926×3 个步骤节点 + 模块结构节点。

**标记法**：用例标题中用 `【反向】` 标注异常/负向用例（122 条），
用 `正向`、`边界` 标注正常流程与边界值用例。

## 二、测试设计方法

用例综合运用了以下方法：

| 方法 | 应用示例 |
|---|---|
| 等价类划分 | 邮箱格式合法/非法、枚举字段有效/无效取值 |
| 边界值分析 | 用户名 3/4/20/21 字符、金额小数位、端口 1/65535/65536 |
| 判定表 | 组合筛选的 AND 逻辑、状态流转分支 |
| 场景法 | 多阶段表单（基础信息 → 定价 → 授权上架 → 完成）全流程 |
| 错误推测法 | 特殊字符 `<>&`、重名、网络异常、并发重复点击 |
| 状态迁移 | 待审核 / 已通过 / 已驳回 / 已开票 / 退票驳回 等状态组合 |

## 三、覆盖特点

**负向用例占比高。** 926 条中 122 条显式标注 `【反向】`，
另有大量以「校验提示」「格式错误」「必填提示」为预期的用例，
不是只覆盖"正常能点通"。

**覆盖异常与边界场景。**
- 空数据、加载失败、网络异常、导出超限
- 分页边界（首页/末页按钮置灰、筛选后重置到第 1 页）
- 长度上下限、特殊字符、重名、不可编辑字段
- 状态约束（如"仅剩一个启用路由时禁止禁用"）

**校验点具体到 UI 细节。**
如表头列数与列名、状态标签颜色圆点、按钮 loading 与置灰、
placeholder 文案、tooltip 截断、行 hover 样式等，
便于执行时逐项核对，减少理解歧义。
